# anyPin 产品设计文档

> 跨工作区多窗口置顶管理器 — 让信息悬浮在你的桌面上

## 一、产品定位

一个 **macOS 优先** 的桌面工具，用户可以通过它快速创建多个全局置顶的小窗口（Widget），每个窗口加载自定义 HTML 内容，始终浮于所有窗口之上，且切换工作区时保持可见。

基于 Tauri v2 开发，Rust 后端 + Web 前端，轻量、快速、安全。

## 二、目标用户

| 用户类型 | 典型场景 | 核心诉求 |
|---|---|---|
| **开发者** | 编码时随时看 CI 状态、倒计时、AI agent 工作进度 | 不离开编辑器也能获取关键信息 |
| **内容创作者/直播主** | 屏幕上始终可见的计时器、提示词、提纲 | 轻量悬浮，不占 OBS 性能 |
| **效率工具爱好者** | 桌面小部件、快捷操作、定制化体验 | 可扩展、可定制、不碍事 |

## 三、核心场景与痛点

> "我的屏幕已经够满了，但有些信息我**必须随时能看到**，又不想占用主工作区。"

| 场景 | 痛点 | anyPin 的解法 |
|---|---|---|
| 编码时看时钟/倒计时 | 切日历 app 太重，菜单栏时钟太隐蔽 | 浮动小钟，半透明不挡视线 |
| 跑 AI agent 时监控状态 | 终端窗口被其他窗口盖住，忘了它在跑 | 一个 100px 的小条实时显示进度 |
| 直播时看计时/提纲 | OBS 嵌入复杂，且 OBS 本身就占性能 | 轻量 HTML widget，零依赖 |
| 跨工作区记临时笔记 | 切 Space 就看不见了 | 置顶 + visibleOnAllWorkspaces |
| 同时看多个数据源 | 开太多窗口，来回切换混乱 | 多个小 widget 并排悬浮 |

## 四、产品原则

1. **轻到感觉不到** — 启动快、内存小、不抢焦点。Widget 是"空气中的信息"，不是"又一个窗口"
2. **零配置可用** — 装完即用，内置模板开箱即用，不需要写代码
3. **写代码能做更多** — 给开发者开放 HTML 模板能力，但这是"进阶"，不是门槛
4. **不打扰** — 默认点击穿透、半透明、小尺寸。用户主动需要时才拉到前台

## 五、功能架构

```
anyPin
├── 系统托盘（主入口）
│   ├── Pin 列表（所有活跃 Widget）
│   ├── 模板库（创建新 Widget）
│   ├── 全局操作（全部显示/隐藏/置顶切换）
│   └── 设置
├── Widget 运行时
│   ├── 窗口管理（置顶、跨工作区、透明度、位置）
│   ├── HTML 渲染引擎（加载模板内容）
│   ├── 数据通道（Widget ↔ Rust 后端 ↔ 外部）
│   └── 交互模式（正常模式 / 点击穿透模式）
├── 模板系统
│   ├── 内置模板（开箱即用）
│   ├── 本地模板（用户自己写的 HTML）
│   └── 社区模板（远期：在线模板市场）
└── 开放能力（给模板用的 API）
    ├── 定时器 / 计时
    ├── HTTP 请求
    ├── 文件读取
    ├── 剪贴板
    └── 系统 Shell 命令输出（受限白名单）
```

## 六、具体功能设计

### 6.1 系统托盘 — 唯一的主入口

不做传统的 Dock 栏 App 窗口。anyPin 的"主界面"就是系统托盘图标。

托盘菜单：

```
📌 anyPin
├── 🕐 新建置顶时钟
├── ⏱️ 新建倒计时
├── 📊 新建状态监控
├── ─────────────
├── 活跃 Pins (3)  ▸
│   ├── ✅ 时钟          点击 → 聚焦
│   ├── ✅ 倒计时 25:00  点击 → 聚焦
│   └── 👁️ CI Status    点击 → 聚焦
├── ─────────────
├── ⌘⇧P 置顶/取消置顶
├── ⌘⇧H 隐藏/显示全部
├── ─────────────
├── 从文件创建 Pin...
├── 模板管理...
├── 设置...
└── 退出
```

### 6.2 Widget 窗口

每个 Widget 是一个独立 WebviewWindow，核心属性：

| 属性 | 默认值 | 说明 |
|---|---|---|
| 置顶 | true | 默认就置顶 |
| 跨工作区 | true | macOS 上默认开启 |
| 透明 | false | 可选 |
| 无边框 | true | 默认无边框 |
| 点击穿透 | false | 用户可切换 |
| 任务栏图标 | false | 不污染任务栏 |
| 尺寸记忆 | — | 记住用户拖拽后的尺寸 |

**交互设计：**
- **右键菜单**：置顶/取消置顶、透明度滑块、点击穿透切换、关闭、编辑
- **拖拽**：按住顶部区域拖拽移动窗口
- **缩放**：窗口右下角拖拽缩放，或滚轮缩放
- **双击**：双击切换点击穿透模式

### 6.3 内置模板

#### 🕐 时钟
- 配置项：12/24 小时制、显示日期、字号、颜色主题
- 预览：半透明圆角矩形，大字显示当前时间

#### ⏱️ 倒计时/番茄钟
- 配置项：时长、循环模式、结束提醒（声音/通知）
- 预览：数字倒计时 + 进度环

#### 📊 状态监控
- 配置项：监控进程、刷新频率
- 预览：实时状态指示灯 + 文字

#### 📝 便签
- 配置项：字体大小、背景色、自动保存
- 预览：可编辑文本区域

### 6.4 自定义模板

**目录结构：**

```
my-template/
├── manifest.json    # 模板元信息
└── index.html       # 模板内容
```

**manifest.json 示例：**

```json
{
  "name": "我的自定义模板",
  "version": "1.0.0",
  "description": "一个自定义 Widget 模板",
  "author": "your-name",
  "defaultSize": { "width": 300, "height": 200 },
  "defaultOpacity": 0.9,
  "permissions": ["timer", "http", "clipboard"]
}
```

**anyPin JS SDK：**

```javascript
// Widget 内可用的 SDK API
window.anyPin.onReady(() => {
  // 初始化
});

window.anyPin.setInterval((elapsed) => {
  // 每秒回调
}, 1000);

window.anyPin.http.fetch('https://api.example.com/status')
  .then(data => {
    document.getElementById('status').textContent = data.status;
  });

window.anyPin.clipboard.read().then(text => {
  // 读取剪贴板
});
```

### 6.5 设置面板

**通用设置：**
- 开机自启
- 全局快捷键配置
- 默认透明度
- 默认置顶行为

**快捷键：**
- ⌘⇧P — 置顶/取消置顶当前聚焦窗口
- ⌘⇧H — 隐藏/显示全部 Widget
- ⌘⇧N — 新建 Widget
- ⌘⇧W — 关闭当前聚焦 Widget

**模板路径：**
- 内置模板路径（只读）
- 用户模板路径（可编辑）
- 自定义模板搜索路径

**高级选项：**
- Widget 渲染引擎设置
- 日志级别
- 数据存储位置

## 十、明确不做什么

- **不做在线模板市场** — v1.0 之前不考虑，社区模板通过 GitHub 仓库共享即可
- **不做 Widget 之间的联动** — 每个 Widget 独立运行，不引入事件总线
- **不做移动端** — 纯桌面工具，移动端置顶无意义
- **不做 Windows 跨工作区 hack** — Windows 虚拟桌面 API 限制太多，投入产出比低
- **不做编辑器** — 模板编辑用 VS Code 等外部编辑器，anyPin 不内嵌

| 产品 | 定位 | 平台 | 价格 |

### 竞品分三层

```
第一层：置顶已有窗口
  Floaty / PinFrame / PowerToys Always On Top
  → 功能单一，仅提供窗口置顶能力

第二层：创建新浮窗
  AlwaysOnTop.app / MenubarX / SnapDraw
  → 提供固定类型的内容浮窗

第三层：可扩展 HTML Widget 引擎 ← anyPin 目标位置
  Electron Widgets（现有开源方案，但基于 Electron 太重）
  → anyPin：Tauri 轻量 + 跨工作区 + 可扩展 SDK
```

### 对标学习要点

| 竞品 | 学习点 |
|---|---|
| **Floaty** | 每窗口指示器、透明度+穿透组合、全局快捷键 |
| **AlwaysOnTop.app** | 多内容类型、桌面宠物（病毒传播力）、一次性买断 |
| **MenubarX** | 4.9 分/15K 评分验证市场需求、自动刷新、iCloud 同步 |
| **Electron Widgets** | Tauri 比其轻 10 倍，这是核心差异化 |

## 十四、核心竞争壁垒

1. **Tauri 轻量** — 安装包 ~15MB，运行内存 ~30MB，对比 Electron 方案 ~150MB
2. **macOS 跨工作区** — `visibleOnAllWorkspaces` 原生支持，竞品几乎都做不到
3. **可扩展 HTML SDK** — 开放创造 vs 固定内容类型，社区驱动的模板生态

## 十五、技术栈

| 层级 | 技术选型 | 说明 |
|---|---|---|
| Frontend | React + TypeScript | 管理界面 + 设置面板 |
| UI 库 | Tailwind CSS + shadcn/ui | 轻量、可定制 |
| Backend | Rust（Tauri v2） | 窗口管理、系统调用、模板引擎 |
| Widget 渲染 | 纯 HTML/CSS/JS | 每个 Widget 独立 Webview |
| 存储 | JSON 文件 | 轻量持久化，无需数据库 |
| 打包 | Tauri bundler | .dmg / .msi / .AppImage |
| 原生能力 | macOS Accessibility API | 置顶已有窗口 |
